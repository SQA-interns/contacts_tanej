# US-010 Filter the contact list

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

## Story

As a member of a group, I want to filter the list by tag, attribute, country and company, so that I can pick exactly the contacts I need, for example everybody tagged `udelezenec2026` but not `neObvescaj`.

## Purpose

Tags and attributes are only useful when they can be used to narrow the list. Without filters the customer cannot exclude contacts tagged `neObvescaj` when selecting contacts for export.

## Definitions

| Term | Meaning |
|---|---|
| Condition | One filter: tag has all, tag has any, tag does not have, key equals value, key exists, country, company. |
| Filter | The set of conditions the user has added; all conditions must hold (AND). |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-010-01 | When the user adds the condition "has all of these tags", the system shall show the contacts that have every named tag (ignoring case, BR-07). | Q-10b |
| R-010-02 | When the user adds the condition "has any of these tags", the system shall show the contacts that have at least one named tag. | Q-10b |
| R-010-03 | When the user adds the condition "does not have tag X", the system shall show the contacts without that tag, including contacts with no tags. | Q-10b |
| R-010-04 | When the user adds the condition "key equals value", the system shall show the contacts that have an attribute with that key (ignoring case) and that value (ignoring case and accents). [ASSUMPTION] | Q-23a |
| R-010-05 | When the user adds the condition "key exists", the system shall show the contacts that have an attribute with that key (ignoring case), even when its value is empty. | Q-23a |
| R-010-06 | When the user adds the condition "country" (chosen from the country list), the system shall show the contacts with that country. | Q-23a |
| R-010-07 | When the user adds the condition "company", the system shall show the contacts whose company equals the typed text ignoring case and accents; the form suggests companies used in the group. [ASSUMPTION] | Q-23a |
| R-010-08 | The system shall combine all conditions and the search text (US-009) with AND. | Q-23a |
| R-010-09 | The system shall offer no other filter and no way to save a filter. | Q-23a |
| R-010-10 | When the user removes a condition or chooses "Clear filters", the system shall update the list and the total at once. | Q-23b |
| R-010-11 | While a condition is active, the system shall show it and let the user remove it. | Q-15 |

## Acceptance criteria

| ID | Given | When | Then | Rules |
|---|---|---|---|---|
| AC-010-01 | Five contacts; three have `udelezenec2026`, one of these also `neObvescaj` | The Editor adds "has `udelezenec2026`" and "does not have `neObvescaj`" | Two contacts are listed; the total is 2 | R-010-01, R-010-03, R-010-08 |
| AC-010-02 | Contacts tagged `a`, `b`, `a`+`b` | "has all of `a`, `b`", then "has any of `a`, `b`" | One contact; then three contacts | R-010-01, R-010-02 |
| AC-010-03 | Ana has `kompetenca=spletnoProgramiranje` | The user adds "key `Kompetenca` equals `SPLETNOPROGRAMIRANJE`" | Ana is listed | R-010-04 |
| AC-010-04 | Two contacts have key `kompetenca`, one has `leto` with empty value | "Key exists `leto`" | The contact with `leto` is listed | R-010-05 |
| AC-010-05 | Contacts in Slovenija and Avstrija | "Country = Slovenija" | Only the Slovenian contacts | R-010-06 |
| AC-010-06 | Contacts of company "Acme" and "Šola" | "Company = acme", then "sola" | The Acme contacts; the Šola contacts | R-010-07 |
| AC-010-07 | A filter is active and the search text is `novak` | The list is shown | Only contacts that satisfy both appear | R-010-08 |
| AC-010-08 | A filter shows nothing | The user presses "Clear filters" | The full list returns | R-010-10 |
| AC-010-09 | A filter is active | The list is shown | The active condition is shown with a control to remove it | R-010-11 |
| AC-010-10 | The user opens the filter dialog | The options are shown | Only the seven conditions are offered; there is no "save filter" | R-010-09 |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-010-01 | "does not have X" and no contact has X | All contacts | R-010-03 |
| EX-010-02 | "has all of" with an unknown tag | No contact; "No contacts match" | R-010-01 |
| EX-010-03 | Key that no contact has | No contact | R-010-05 |
| EX-010-04 | Contact in Trash satisfies the filter | Not listed | R-010-08 |
| EX-010-05 | Filter on a tag name of another group | No contact; the other group's data is never revealed | R-010-01 |
| EX-010-06 | Value with `%`, `'` | Treated as plain text | R-010-04 |
| EX-010-07 | 10,000 contacts and three conditions | Result in under 1 second (NFR-01) | R-010-08 |
| EX-010-08 | Contact with empty country | Never matches a country condition | R-010-06 |

## Out of scope

Saved filters; OR between different conditions; filters on phone, notes, city or dates; "has no attribute" filters.
