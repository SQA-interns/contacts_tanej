# US-020 View, compare and restore versions

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

## Story

As an Owner or Editor, I want to open an earlier version of a contact, compare it with the current one and restore it, so that I can undo a wrong change or a wrong merge.

## Purpose

The customer accepts the product only when versions work (Q-19). Without the screens the recorded versions are of no use.

## Definitions

| Term | Meaning |
|---|---|
| Compare | A side-by-side view of a version and the current contact in which changed fields are highlighted. |
| Restore | Make the contact's predefined fields, tags and attributes equal to those of the chosen version. |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-020-01 | While the user is an Owner or Editor, the system shall show a Versions tab on each contact that lists the versions (number, who, when), newest first. | Q-29a |
| R-020-02 | When the user opens a version, the system shall show it read-only. | Q-29a |
| R-020-03 | When the user compares a version with the current contact, the system shall highlight the fields, tags and attributes that differ. | Q-29a |
| R-020-04 | When an Owner or Editor confirms a restore of a version, the system shall bring back all predefined fields, tags and attributes as they were, record a new version (US-019) and write a History entry that names the restored version number and the changed fields (US-013). | Q-29a |
| R-020-05 | If the contact is in Trash, then the system shall refuse a restore and tell the user to restore the contact from Trash first. | Q-29a |
| R-020-06 | If the chosen version equals the current contact, then the system shall change nothing and say so. (confirmed by the developer) | Q-29 |
| R-020-07 | While the user is a Viewer, the system shall show no Versions tab and shall refuse version requests (BR-02). | Q-06b |
| R-020-08 | If the contact was changed by someone else since the user opened the Versions tab, then the system shall refuse the restore as a conflict (US-005 R-005-08). (confirmed by the developer) | Q-18 |
| R-020-09 | The system shall ask for confirmation before a restore. | Q-29a |

## Acceptance criteria

| ID | Given | When | Then | Rules |
|---|---|---|---|---|
| AC-020-01 | "Ana Novak" has versions 1 to 3 | Marko opens the Versions tab | Three versions, newest first, with name and time | R-020-01 |
| AC-020-02 | As above | He opens version 1 | It is shown read-only | R-020-02 |
| AC-020-03 | Version 1 has phone `+386 40 123 456`, the current one `+386 41 555 123` | He compares them | The phone is highlighted; unchanged fields are not | R-020-03 |
| AC-020-04 | As above | He confirms a restore of version 1 | The contact has phone `+386 40 123 456`, the tags and attributes of version 1; version 4 exists; the History names version 1 and field "Phone" | R-020-04 |
| AC-020-05 | The contact is in Trash | He tries to restore a version | Refused with the hint | R-020-05 |
| AC-020-06 | Version 3 equals the current contact | He restores version 3 | Nothing changes; no new version; he is told | R-020-06 |
| AC-020-07 | Petra is a Viewer | She looks for versions | No tab; API refused (403) | R-020-07 |
| AC-020-08 | The restore dialog is open | He cancels | Nothing changes | R-020-09 |
| AC-020-09 | Boris saved a change after Marko opened the tab | Marko confirms a restore | Refused as a conflict; contact unchanged | R-020-08 |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-020-01 | Restoring version 1 after the contact was trashed and restored from Trash | Allowed | R-020-04, R-020-05 |
| EX-020-02 | A version has 50 tags and the current one 50 other tags | All restored; none of the current left | R-020-04 |
| EX-020-03 | A version number that does not exist | "Not found" | R-020-02 |
| EX-020-04 | A version of another contact by id | "Not found" | R-020-02 |
| EX-020-05 | A restore after a merge (survivor) | Contact has the pre-merge values; the merged-away contacts stay in Trash | R-020-04 |
| EX-020-06 | Restore twice in a row | Second one says nothing to change | R-020-06 |

## Out of scope

Restoring a Trash state; deleting versions; restoring one field only; comparing two old versions.
