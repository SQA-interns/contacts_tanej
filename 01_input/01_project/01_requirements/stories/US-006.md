# US-006 Tag contacts

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

## Story

As an Owner or Editor, I want to put free tags on contacts, so that I can group contacts into categories such as `udelezenec2025`.

## Purpose

The customer sorts contacts into categories (for example `neObvescaj`). Without tags the contacts cannot be selected by category for export or filtering.

## Definitions

| Term | Meaning |
|---|---|
| Tag name | 1 to 50 characters: letters, digits, "-" and "_"; no spaces. Letters are Unicode letters (č, š, ž allowed). (confirmed by the developer) |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-006-01 | When an Owner or Editor adds a tag name to a contact and saves, the system shall attach the tag to the contact; if no tag of that name (ignoring case, BR-07) exists in the group, the system shall create it with the spelling typed. | Q-10, Q-10a |
| R-006-02 | If a tag of that name (ignoring case) already exists in the group, then the system shall use the existing tag with its existing spelling. | Q-10 |
| R-006-03 | If a tag name has fewer than 1 or more than 50 characters, or a character other than a letter, digit, "-" or "_", then the system shall refuse the save and store nothing. | Q-10 |
| R-006-04 | If a save would give a contact more than 50 tags, then the system shall refuse it and store nothing. | Q-10 |
| R-006-05 | The system shall keep tags per group; the same name in two groups is two independent tags, and a group never shows another group's tags. | Q-10 |
| R-006-06 | When an Owner or Editor removes a tag from a contact and saves, the system shall detach it from that contact only. | Q-10 |
| R-006-07 | When the last contact loses a tag, the system shall no longer offer that tag in the group. Confirmed by the developer: there is no separate tag list (Q-10a). | Q-10a |
| R-006-08 | The system shall treat a tag as a label only: it shall not change any behaviour, and shall send nothing to anyone because of a tag. | Q-10c |
| R-006-09 | The system shall show every member the tags of a contact; a Viewer cannot change them (BR-02). | Q-06 |
| R-006-10 | When a user types in the tag box, the system shall suggest tags of the group that match the typed text; it shall never force a suggestion. (confirmed by the developer) | Q-15 |

## Acceptance criteria

| ID | Given | When | Then | Rules |
|---|---|---|---|---|
| AC-006-01 | Contact "Ana Novak" exists; the group has no tags | Ana (Owner) adds the tag `udelezenec2025` and saves | The contact shows `udelezenec2025`; the tag is offered in the group | R-006-01 |
| AC-006-02 | The tag `udelezenec2025` exists | Marko adds `UDELEZENEC2025` to another contact | That contact gets the existing tag, shown as `udelezenec2025` | R-006-02 |
| AC-006-03 | The contact form is open | Ana adds the tag `neka značka` (space) | The save is refused naming the tag; nothing is stored | R-006-03 |
| AC-006-04 | A contact has 50 tags | Ana adds a 51st and saves | The save is refused; the contact keeps its 50 tags | R-006-04 |
| AC-006-05 | Group A has `neObvescaj`; Boris owns group B | Boris opens his tag suggestions | `neObvescaj` is not shown to him | R-006-05, R-006-10 |
| AC-006-06 | Ana's contact has `udelezenec2025` and `neObvescaj` | Ana removes `neObvescaj` and saves | Only `udelezenec2025` remains; other contacts keep `neObvescaj` | R-006-06 |
| AC-006-07 | Petra is a Viewer | She opens a tagged contact | She sees the tags and has no control to change them | R-006-09 |
| AC-006-08 | `neObvescaj` was put on a contact | Any user does any action | Nothing is sent; no behaviour of the system changes | R-006-08 |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-006-01 | Tag name of exactly 50 characters; of 51 | Accepted; refused | R-006-03 |
| EX-006-02 | Tag `a-b_c9` | Accepted | R-006-03 |
| EX-006-03 | Tag `a.b`, `a b`, `a/b`, empty | Refused | R-006-03 |
| EX-006-04 | Tag `čaj2026` | Accepted | R-006-03 |
| EX-006-05 | Same tag typed twice on one contact (`Vip`, `vip`) | The contact has the tag once | R-006-02 |
| EX-006-06 | Exactly 50 tags after the save | Accepted | R-006-04 |
| EX-006-07 | The last contact with the tag `old` loses it | `old` is no longer offered in the group | R-006-07 |
| EX-006-08 | A tag is added while another user edits the same contact | Conflict rule of US-005 applies | R-006-01 |

## Out of scope

A separate tag list maintained apart from the contacts; renaming and deleting tags (US-007); tag colours; tag hierarchy; any system meaning of a tag; tag filters (US-010).
