# US-021 Find duplicate contacts

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

## Story

As an Owner or Editor, I want the product to find contacts that are probably the same person, so that I can clean up my list.

## Purpose

Contacts come from Excel sheets and e-mail lists, so the same person is entered twice and gets two mailings. The product does not forbid a second contact with the same e-mail (Q-08c), so it must be able to report it.

## Definitions

| Term | Meaning |
|---|---|
| Certain duplicate | Two contacts with the same e-mail address ignoring case (BR-07). |
| Probable duplicate | Two contacts with the same first and last name (ignoring case and accents) and, in addition, the same company (ignoring case and accents) or the same phone number. |
| Duplicate set | Contacts linked to each other, directly or through others, by a certain or probable match. [ASSUMPTION] A set is "certain" if one of its links is an e-mail match, otherwise "probable". |
| Same phone number | Equal after removing every character other than digits and "+". [ASSUMPTION] |
| Dismissed set | A set marked "not a duplicate". It is identified by exactly the contacts in it. |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-021-01 | When an Owner or Editor presses "Find duplicates", the system shall search all contacts of the group that are not in Trash, regardless of the current filter. | Q-27a |
| R-021-02 | The system shall report a certain duplicate for contacts with the same e-mail address ignoring case. | Q-27 |
| R-021-03 | The system shall report a probable duplicate for contacts with the same first and last name (ignoring case and accents) and the same company or the same phone number. | Q-27 |
| R-021-04 | The system shall not report contacts that match by name alone. | Q-27 |
| R-021-05 | The system shall never match a contact that has no e-mail, no first name, no last name and no company (for example one with only a phone). | Q-27 |
| R-021-06 | The system shall match contacts of one group only, never across groups. | Q-27 |
| R-021-07 | The system shall show the result as a list of duplicate sets, each marked certain or probable with the reason (for example "same e-mail"). | Q-27a |
| R-021-08 | The system shall change no contact and create no version when searching, and shall search only when the user starts it. | Q-27a |
| R-021-09 | When an Owner or Editor marks a set "not a duplicate", the system shall not show a set of exactly the same contacts again, even when those contacts are edited later; the mark changes no contact and creates no version. | Q-27a, Q-28a |
| R-021-10 | If a set contains a contact that was not in a dismissed set, then the system shall show the set. | Q-28a |
| R-021-11 | While the user is a Viewer, the system shall show no "Find duplicates" and shall refuse the request (BR-02). [ASSUMPTION] Owner and Editor only. | Q-06 |
| R-021-12 | If no duplicate is found, then the system shall say "No duplicates found". | Q-15 |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-021-01 | Names `Škerlj` and `Skerlj`, same company | Probable | R-021-03 |
| EX-021-02 | Novak / Nowak | Not reported (no fuzzy matching) | R-021-03 |
| EX-021-03 | Empty e-mail on both contacts | Not an e-mail match | R-021-02 |
| EX-021-04 | A, B, C where A–B share e-mail and B–C share name and company | One set A, B, C marked certain | R-021-02, R-021-03 |
| EX-021-05 | Dismissed set A, B, C; B is moved to Trash | The new set A, C is a different set and is shown | R-021-09, R-021-10 |
| EX-021-06 | Two empty first names, same last name and company | Not reported: name needs first and last | R-021-03 |
| EX-021-07 | Two contacts without e-mail and name but the same company | Never matched | R-021-05 |
| EX-021-08 | Phone `+386 41 555 123` and `041 555 123` | Not the same (different digits) | R-021-03 |

## Out of scope

Fuzzy matching; running on save; undoing a "not a duplicate" mark; merging (US-022); matching across groups; automatic actions.
