# US-013 History of contact changes

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

## Story

As an Owner or Editor, I want a History that records who changed what and when, shown on every contact, so that I can see and trust every change and every export of personal data.

## Purpose

The customer asks for an audit trail of all contact changes. Without it nobody can tell who changed or exported personal data.

## Definitions

| Term | Meaning |
|---|---|
| History entry | One record of one event: who, when, what happened, and for changes the field name with old and new value. |
| Save group | The entries written by one save are shown together. |
| Erasure marker | The text "[erased]" that replaces personal data in History entries of an erased contact. [ASSUMPTION] |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-013-01 | When a contact is created, edited, moved to Trash, restored or erased, the system shall append a History entry. | Q-25 |
| R-013-02 | When a tag or an attribute is added to or removed from a contact, the system shall append a History entry with the tag name or the key and value. | Q-25 |
| R-013-03 | When a tag is renamed or deleted for the group (US-007), the system shall append one History entry per affected contact with the old and new tag name. | Q-10a, Q-25 |
| R-013-04 | When an Owner or Editor exports (US-011), the system shall append a History entry with who, when and the number of exported contacts. | Q-24b |
| R-013-05 | When a member is invited, a role is changed, a member is removed or leaves, an invitation is cancelled, or a group is deleted or restored, the system shall append a group-level History entry. [ASSUMPTION] A leaving is recorded as a removal by the member. | Q-25 |
| R-013-06 | Where merging (US-022) or restoring a version (US-020) exists, the system shall append a History entry for each such event as those stories describe. | Q-25, Q-28, Q-29a |
| R-013-07 | The system shall record in each entry the user's name and e-mail, the time (stored in UTC, shown in the project time zone), and for every changed field its name, old value and new value; entries of one save are grouped. | Q-25a |
| R-013-08 | The system shall not record viewing or searching. | Q-25 |
| R-013-09 | While the user is an Owner or Editor, the system shall show on each contact a History tab, newest first. | Q-25b |
| R-013-10 | The system shall let nobody change or delete a History entry, through the UI or the API; the only change is the anonymisation after an erasure (BR-06) or after an account deletion (US-016). | Q-25b |
| R-013-11 | The system shall keep History entries as long as the group exists and delete them with the group. | Q-25b |
| R-013-12 | When a contact is erased, the system shall keep its History entries and replace the contact's personal data in them with the erasure marker (BR-06). | Q-06e |
| R-013-13 | While the user is a Viewer, the system shall show no History and shall refuse History requests (BR-02). | Q-06b |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-013-01 | A save with no change | No entry | R-013-01 |
| EX-013-02 | Time stored `2026-07-01T22:30:00Z` | Shown as 2026-07-02 00:30 in Europe/Ljubljana (summer time) | R-013-07 |
| EX-013-03 | The actor's account is deleted later | Name stays, e-mail removed (US-016) | R-013-10 |
| EX-013-04 | A removed member's earlier entries | Remain with the name | R-013-11 |
| EX-013-05 | An old value is empty | Shown as empty, not as missing | R-013-07 |
| EX-013-06 | The group is deleted for good | All its History is deleted | R-013-11 |
| EX-013-07 | A value of 5,000 characters (notes) changes | Old and new value are both kept in full | R-013-07 |
| EX-013-08 | A failed or refused save | No entry | R-013-01 |

## Out of scope

History export; History of a Viewer's views; editing or deleting entries; the group-wide screen and its filters (US-014); versions (US-019, US-020).
