# US-019 Record versions of a contact

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

## Story

As an Owner or Editor, I want the product to keep a full copy of a contact at each change, so that an earlier state can be viewed and restored later (US-020).

## Purpose

Versions can only be shown if they were recorded from the first save. Confirmed by the developer: the interview puts versions (F10) in the second increment; the recording is placed in the MVP so that no data is lost, and only the screens (US-020) come later.

## Definitions

| Term | Meaning |
|---|---|
| Version | A full snapshot of the predefined fields, tags and attributes of one contact, with a running number (1, 2, 3, …), who made it and when. |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-019-01 | When a contact is created, the system shall record version 1. | Q-29 |
| R-019-02 | When a save changes a predefined field, a tag or an attribute of one contact, the system shall record the next version number; a save without a change shall record none. | Q-29 |
| R-019-03 | The system shall record no version when a tag is renamed or deleted for the whole group (US-007). | Q-29 |
| R-019-04 | Where merging exists (US-022), the system shall record one version on the survivor; where restoring a version exists (US-020), the system shall record the restore as a new version. | Q-29 |
| R-019-05 | The system shall never reuse or lower a version number of a contact. | Q-29 |
| R-019-06 | While the user is an Owner or Editor, the system shall return the list of a contact's versions (number, user, time) on request; a Viewer's request shall be refused (BR-02). | Q-29a |
| R-019-07 | The system shall keep versions as long as the contact exists and erase them with it (BR-06). | Q-29b |
| R-019-08 | The system shall not limit the number of versions per contact. | Q-29b |

## Acceptance criteria

| ID | Given | When | Then | Rules |
|---|---|---|---|---|
| AC-019-01 | Ana (Owner) creates "Ana Novak" | The version list is requested | One version, number 1, by Ana | R-019-01, R-019-06 |
| AC-019-02 | Version 1 exists | Marko changes the phone and saves | Version 2 by Marko exists | R-019-02 |
| AC-019-03 | Version 2 exists | A save with no change | Still version 2 | R-019-02 |
| AC-019-04 | Version 2 exists | A tag is added and saved | Version 3 exists | R-019-02 |
| AC-019-05 | A tag on the contact is renamed for the group | The version list is requested | No new version | R-019-03 |
| AC-019-06 | Petra is a Viewer | She requests the version list | Refused (403) | R-019-06 |
| AC-019-07 | Version 3 exists | The contact is erased | The versions are gone with it | R-019-07 |
| AC-019-08 | A conflicting save is refused (US-005) | The version list is requested | No version for the refused save | R-019-02 |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-019-01 | 500 changes to one contact | 501 versions, in order | R-019-08 |
| EX-019-02 | Contact is trashed and restored from Trash | No new version (state, not content) | R-019-02 |
| EX-019-03 | A version is recorded, then the account of its author is deleted | The version stays with the author's name (US-016) | R-019-05 |
| EX-019-04 | A save refused by validation | No version | R-019-02 |

## Out of scope

Screens to view, compare and restore (US-020); a limit or cleanup of old versions.
