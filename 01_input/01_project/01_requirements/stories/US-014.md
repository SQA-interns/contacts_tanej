# US-014 Group-wide History view with filters

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

## Story

As an Owner or Editor, I want to see all History entries of my group and filter them by person, event type and date, so that I can answer "who did what, and when" without opening every contact.

## Purpose

The per-contact tab answers questions about one contact. Questions such as "what did Marko change last week" or "who exported contacts" need one view of the whole group.

## Definitions

| Term | Meaning |
|---|---|
| Event type | One of the kinds of event in US-013: created, edited, deleted, restored, erased, tag changed, attribute changed, tag renamed or deleted, exported, member event, group deleted or restored, merged, version restored. |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-014-01 | While the user is an Owner or Editor, the system shall show the group-wide History, newest first, 25 entries per page. [ASSUMPTION] page size as in the list. | Q-25b |
| R-014-02 | When the user picks a person, the system shall show only the entries made by that person. | Q-25b |
| R-014-03 | When the user picks one or more event types, the system shall show only entries of those types. | Q-25b |
| R-014-04 | When the user picks a date range, the system shall show the entries whose time falls on a day from the first to the last day inclusive, days taken in the project time zone. | Q-25b, Q-26 |
| R-014-05 | The system shall combine the person, event type and date range with AND. | Q-25b |
| R-014-06 | If no entry matches, then the system shall show "No entries match" and a "Clear filters" button. | Q-15 |
| R-014-07 | While the user is a Viewer, the system shall show no group-wide History and shall refuse the request (BR-02). | Q-06b |
| R-014-08 | The system shall show in the group-wide History only entries of the user's own group. | Q-13 |

## Out of scope

History export; free-text search of History; changing entries.
