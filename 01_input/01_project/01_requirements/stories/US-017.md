# US-017 Secured REST API with OpenAPI description

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

## Story

As the web app (and so every user), I want one secured REST API with a published description, so that every action is checked for identity, group and role, and other tools can be connected later.

## Purpose

The customer asks that the back end is reachable only through a properly secured REST interface and that data of different groups is isolated. Without one common check every endpoint could forget it.

## Definitions

| Term | Meaning |
|---|---|
| ID token | The Firebase ID token the web app sends in the header `Authorization: Bearer <token>`. |
| Error response | The one JSON format for every failure: an HTTP status, a machine-readable `code` and a short `message`; no stack trace. |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-017-01 | The system shall require a valid Firebase ID token on every endpoint except the health check. | Q-12 |
| R-017-02 | If the token is missing, malformed, expired or not issued for this Firebase project, then the system shall answer 401 and return no data. | Q-12 |
| R-017-03 | If the token is valid but the user's e-mail is not verified, then the system shall answer 403 with the code `EMAIL_NOT_VERIFIED` and return no data (BR-03). Status and code confirmed by the developer. | Q-12 |
| R-017-04 | The system shall take the group only from the request path (`/groups/{id}/…`), never from the request body or query. | Q-12 |
| R-017-05 | If the user is not a member of the group, or the group does not exist, then the system shall answer 404 with the same response in both cases, and return no data (BR-01). | Q-12, Q-13 |
| R-017-06 | If the user is a member whose role does not allow the operation, then the system shall answer 403 (BR-02). | Q-12 |
| R-017-07 | When the request breaks a validation rule of a story, the system shall answer 400 with the code of the rule and the name of the field and store nothing. Status confirmed by the developer. | Q-12a |
| R-017-08 | If a user sends more than the allowed number of requests in one minute, then the system shall answer 429 with a `Retry-After` header for the rest of that minute. The limit is per user and a configuration value with the default 100 (confirmed by the developer; tests may set it lower). | Q-12b |
| R-017-09 | If a request body is larger than 1 MB, then the system shall answer 413 and process nothing (confirmed by the developer). | Q-12b |
| R-017-10 | The system shall answer every failure with the error response format and show no stack trace. | Q-12c |
| R-017-11 | The system shall publish an OpenAPI description that lists every endpoint, its request, its responses and its errors, and the web app shall use this same API. | Q-02a |
| R-017-12 | The system shall offer an endpoint without authentication that answers 200 while the system and its database work, and 503 otherwise. (confirmed by the developer) | Q-15b |
| R-017-13 | The system shall exchange JSON in UTF-8, with field names in English. | Q-11, Q-11a |
| R-017-14 | The system shall offer API access to nobody but the user's own web app in the MVP; it shall issue no API keys. | Q-02a, Q-22 |
| R-017-15 | If a conflicting write is refused (US-005 R-005-08), then the system shall answer 409 with the code `CONFLICT` and the current values. Status confirmed by the developer. | Q-18 |

## Acceptance criteria

| ID | Given | When | Then | Rules |
|---|---|---|---|---|
| AC-017-01 | No token | Any endpoint except the health check is called | 401, error response, no data | R-017-01, R-017-02 |
| AC-017-02 | An expired token; a token of another Firebase project | The contact list is requested | 401 | R-017-02 |
| AC-017-03 | A valid token of a user with an unverified e-mail | A group is requested | 403 `EMAIL_NOT_VERIFIED` | R-017-03 |
| AC-017-04 | Boris owns group B; Ana is not a member | Ana requests B's contacts by `/groups/{B}/…` | 404, identical to the response for an id that does not exist | R-017-05 |
| AC-017-05 | Ana sends a request to her group A with the body containing `"groupId": B` | The request is processed | A is used; B is ignored; nothing changes in B | R-017-04 |
| AC-017-06 | Petra is a Viewer | She calls the export endpoint | 403 | R-017-06 |
| AC-017-07 | Every operation listed in the OpenAPI description that has a group in its path | A non-member calls each one | Each answers 404 (one test per operation) | R-017-05 |
| AC-017-08 | A valid user | Sends 101 requests within one minute | The 101st gets 429 with `Retry-After` | R-017-08 |
| AC-017-09 | A request body of 1 MB + 1 byte | Sent to a create-contact endpoint | 413; nothing stored | R-017-09 |
| AC-017-10 | Any failure above | The response is read | It has `code` and `message`; no stack trace | R-017-10 |
| AC-017-11 | The system is running | The OpenAPI description is fetched | It lists each endpoint of the stories with requests, responses and errors | R-017-11 |
| AC-017-12 | The database is stopped | The health check is called | 503; with the database back, 200 | R-017-12 |
| AC-017-13 | A request with an invalid contact (e.g. e-mail `ana.novak@`) | Sent | 400 with the code and the field `email`; nothing stored | R-017-07 |
| AC-017-14 | Two Editors save the same contact in turn from the same starting value | The second save is sent | 409 `CONFLICT` with the current values | R-017-15 |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-017-01 | Header `Authorization: Basic …` | 401 | R-017-02 |
| EX-017-02 | Group id with a wrong format (not an id) | 404 | R-017-05 |
| EX-017-03 | A removed member with an old but valid token | 404 on the next request | R-017-05 |
| EX-017-04 | Exactly 100 requests in a minute | All answered normally | R-017-08 |
| EX-017-05 | Exactly 1 MB body | Processed | R-017-09 |
| EX-017-06 | A group in Trash requested by a non-Owner member | 404 | R-017-05 |
| EX-017-07 | HTTP method not allowed on a path | Error response with status 405 | R-017-10 |
| EX-017-08 | A trashed contact id of another group | 404 | R-017-05 |
| EX-017-09 | The health check without a token | 200 | R-017-01 |

## Out of scope

API keys or tokens for other tools; direct use by other tools (open for later); an API version policy; webhooks; sign-in endpoints (Firebase handles them). Transport, headers and logging are in `security-requirements.md`.
