# US-005 Create, view and edit a contact

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

## Story

As an Owner or Editor, I want to create, view and edit a contact with its predefined fields, so that the contact data of my project is complete and current in one place.

## Purpose

The contact is the heart of the product. Without it nothing can be found, tagged or exported; without the conflict rule two people silently overwrite each other's changes.

## Definitions

| Term | Meaning |
|---|---|
| Predefined fields | The 11 fields of the data model: first name, last name, e-mail, phone, company, job title, street and house number, postal code, city, country, notes. |
| Contact screen | The screen that shows one contact; Owners and Editors edit on it. |
| Contact number | The contact's current version number (US-019); the screen carries it when it opens, to detect a conflict. |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-005-01 | When an Owner or Editor saves a new contact with valid data, the system shall store it in the group and show it. | Q-07a |
| R-005-02 | If none of first name, last name, e-mail and company has a character other than spaces, then the system shall refuse the save and store nothing. | Q-08a |
| R-005-03 | If a field breaks a constraint of the data model (BR-05), then the system shall refuse the whole save, name the field and the reason, and store nothing. | Q-08b |
| R-005-04 | The system shall store an e-mail address in lowercase. | Q-08b |
| R-005-05 | The system shall allow a second contact with the same e-mail address in the same group, without a warning. | Q-08c |
| R-005-06 | When any member opens a contact, the system shall show its predefined fields, tags (US-006) and attributes (US-008). | Q-07a |
| R-005-07 | When an Owner or Editor saves changes to a contact, the system shall store the new values and show the saved contact. | Q-07a |
| R-005-08 | If the contact was changed by someone else since the user opened it, then the system shall refuse the save, show the message "this contact was changed by someone else" and the new values, and overwrite nothing. | Q-18 |
| R-005-09 | While the user is a Viewer, the system shall show no create or edit control and shall refuse create and edit requests (BR-02). | Q-06 |
| R-005-10 | If a contact is in Trash, then the system shall refuse any edit of it (US-012). | Q-06c |

## Acceptance criteria

| ID | Given | When | Then | Rules |
|---|---|---|---|---|
| AC-005-01 | Ana (Owner) is in "Konferenca 2026" | She saves a contact with first name "Ana", last name "Novak", e-mail `ana.novak@example.com`, company "Acme" | The contact is stored and shown with exactly these values | R-005-01, R-005-06 |
| AC-005-02 | The contact form is open | Ana saves with only phone `+386 40 123 456` filled | The save is refused (one of first name, last name, e-mail, company needed); nothing is stored | R-005-02 |
| AC-005-03 | The contact form is open | Ana saves with e-mail `ANA.Novak@Example.com` and last name "Novak" | The stored e-mail is `ana.novak@example.com` | R-005-04 |
| AC-005-04 | The contact form is open | Ana saves with e-mail `ana.novak@` | The save is refused naming the e-mail field; nothing is stored | R-005-03 |
| AC-005-05 | Contact "Ana Novak" exists | Ana saves another contact with e-mail `ana.novak@example.com` | Both contacts exist; no warning is shown | R-005-05 |
| AC-005-06 | Marko (Editor) changes Ana's phone to `+386 41 555 123` | He saves | The contact shows the new phone | R-005-07 |
| AC-005-07 | Marko and Boris (Editor) both open "Ana Novak" | Marko saves; then Boris saves another change | Boris's save is refused with "this contact was changed by someone else", the new values are shown, Marko's change is intact | R-005-08 |
| AC-005-08 | Petra is a Viewer | She opens "Ana Novak" | All values are shown; there are no edit controls; an edit request through the API is refused (403) | R-005-06, R-005-09 |
| AC-005-09 | Ana's contact is in Trash | Marko tries to save a change to it | The save is refused; the contact is unchanged | R-005-10 |
| AC-005-10 | The contact form is open | Ana saves with country "Slovenija" typed freely, which is not in the country list | The save is refused naming the country field | R-005-03 |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-005-01 | Only company "Acme" filled | Saved | R-005-02 |
| EX-005-02 | First name `   ` (spaces) and all others empty | Refused | R-005-02 |
| EX-005-03 | Text field of exactly 255 characters | Saved | R-005-03 |
| EX-005-04 | Text field of 256 characters | Refused naming the field | R-005-03 |
| EX-005-05 | Notes of exactly 5,000 characters; of 5,001 | Saved; refused | R-005-03 |
| EX-005-06 | Phone `abc` (letters) | Refused | R-005-03 |
| EX-005-07 | Phone as typed `040/123-456` | Saved as typed | R-005-03 |
| EX-005-08 | Valid country chosen from the list | Saved | R-005-03 |
| EX-005-09 | Save with no change | Nothing is written; no new version, no History entry | R-005-07 |
| EX-005-10 | Two failed fields in one save | Whole save refused; both fields named | R-005-03 |
| EX-005-11 | Contact is opened by a member of another group | "Not found" | R-005-06 |
| EX-005-12 | Contact is trashed by someone else while the user edits | Save refused; the user is told it is in Trash | R-005-10 |

## Out of scope

Several e-mails or phones per contact; typed values; uniqueness of e-mail; photo or attachments; import (see US-011's out of scope); tags and attributes (US-006, US-008); trash and delete (US-012).
