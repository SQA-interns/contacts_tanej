# US-008 Free key-value attributes on a contact

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

## Story

As an Owner or Editor, I want to add my own key-value attributes to a contact, such as `kompetenca=spletnoProgramiranje`, so that I can keep facts the predefined fields do not cover.

## Purpose

Every project needs different facts about its contacts. Without free attributes users stuff them into the notes where they cannot be filtered or exported by column.

## Definitions

| Term | Meaning |
|---|---|
| Attribute | A pair of a key and a value, both single text. |
| Key | 1 to 50 characters, trimmed. Any characters (confirmed by the developer). |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-008-01 | When an Owner or Editor adds a key and a value to a contact and saves, the system shall store the attribute on that contact. | Q-09 |
| R-008-02 | If the key equals another key of the same contact ignoring case (BR-07), then the system shall refuse the save and store nothing. | Q-09 |
| R-008-03 | If a key has fewer than 1 or more than 50 characters, or a value has more than 255 characters, then the system shall refuse the save and store nothing. An empty value is allowed (confirmed by the developer). | Q-09 |
| R-008-04 | If a save would give a contact more than 50 attributes, then the system shall refuse it and store nothing. | Q-09 |
| R-008-05 | When the user types a key, the system shall suggest keys already used in the group and shall never force a suggestion. | Q-09 |
| R-008-06 | The system shall treat a value as a single text and shall not interpret it as a number or date. | Q-09 |
| R-008-07 | When an Owner or Editor removes an attribute from a contact and saves, the system shall remove it from that contact only. | Q-09 |
| R-008-08 | While the user is a Viewer, the system shall show the attributes and no control to change them (BR-02). | Q-06 |

## Acceptance criteria

| ID | Given | When | Then | Rules |
|---|---|---|---|---|
| AC-008-01 | Contact "Ana Novak" | Ana adds `kompetenca` = `spletnoProgramiranje` and saves | The contact shows the attribute | R-008-01 |
| AC-008-02 | Ana has `kompetenca` | She adds `Kompetenca` = `java` | The save is refused; the contact is unchanged | R-008-02 |
| AC-008-03 | Another contact has `kompetenca` | Ana starts typing `kom` on a different contact | `kompetenca` is suggested; she may type `komp2` instead and save | R-008-05 |
| AC-008-04 | A contact has 50 attributes | Ana adds a 51st | Refused; the contact keeps 50 | R-008-04 |
| AC-008-05 | Ana adds key `leto` with value `2025` | She saves | The value is stored and shown as the text `2025` | R-008-06 |
| AC-008-06 | The contact has `kompetenca` | Ana removes it and saves | The attribute is gone from this contact only | R-008-07 |
| AC-008-07 | Petra is a Viewer | She opens a contact with attributes | She sees them with no edit control | R-008-08 |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-008-01 | Key of exactly 50 characters; of 51; empty | Accepted; refused; refused | R-008-03 |
| EX-008-02 | Value of exactly 255 characters; of 256 | Accepted; refused | R-008-03 |
| EX-008-03 | Exactly 50 attributes after the save | Accepted | R-008-04 |
| EX-008-04 | Empty value | Accepted | R-008-03 |
| EX-008-05 | Keys `Ključ` and `kljuc` on one contact | Two different keys (only case is ignored, not accents) | R-008-02 |
| EX-008-06 | Key with leading or trailing spaces | Spaces are trimmed before the checks | R-008-03 |

## Out of scope

Typed values (numbers, dates); a key list maintained apart from the contacts; renaming a key for the group; several values per key.
