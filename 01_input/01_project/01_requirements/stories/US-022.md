# US-022 Merge duplicate contacts

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

## Story

As an Owner or Editor, I want to merge two or more duplicate contacts into one and choose the value to keep for each field, so that every person is in my list once, with the best data.

## Purpose

Finding duplicates is of no use if cleaning up means copying values by hand. Merging is destructive, so nothing may happen without the user's explicit choice and a way back.

## Definitions

| Term | Meaning |
|---|---|
| Survivor | The oldest contact of the merge (by time of creation); it stays, with its History, and receives the chosen values. |
| Merged-away contacts | The other contacts of the merge; they go to Trash. |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-022-01 | When an Owner or Editor picks two or more contacts of one duplicate set (US-021) and chooses "Merge", the system shall show a side-by-side screen with the contacts field by field. | Q-28 |
| R-022-02 | The system shall preselect for each predefined field the first non-empty value of the oldest contact first, and let the user choose another contact's value. | Q-28 |
| R-022-03 | The system shall combine the tags of all merged contacts, each tag once (ignoring case). | Q-28 |
| R-022-04 | The system shall combine the attributes of all merged contacts; if the same key (ignoring case) has different values, then the system shall ask the user to choose and shall not allow confirmation before the choice. | Q-28 |
| R-022-05 | When the user confirms, the system shall keep the survivor with the chosen values, move the merged-away contacts to Trash (BR-04) and write one History entry that lists the merged contacts and the chosen values (US-013), and record one version on the survivor (US-019). | Q-28, Q-29 |
| R-022-06 | The system shall show in the survivor's History the History of the merged-away contacts, linked to the survivor. | Q-28 |
| R-022-07 | When a merged-away contact is restored from Trash, the system shall bring back only that contact and shall not change the survivor. | Q-28 |
| R-022-08 | The system shall tell the user on the merge screen that the survivor can be reverted by restoring its earlier version (US-020). | Q-28 |
| R-022-09 | If the merged result would break a limit of BR-05, US-006 or US-008 (for example more than 50 tags or attributes), then the system shall refuse the confirmation, name the limit and change nothing. (confirmed by the developer) | Q-28 |
| R-022-10 | If fewer than two contacts are picked, or a contact is merged with itself, or a contact belongs to another group, then the system shall refuse and change nothing. | Q-28 |
| R-022-11 | The system shall never merge automatically. | Q-28 |
| R-022-12 | If any of the contacts was changed by someone else since the user opened the merge screen, then the system shall refuse the merge as a conflict and change nothing. (confirmed by the developer) | Q-18 |
| R-022-13 | While the user is a Viewer, the system shall show no "Merge" and shall refuse the request (BR-02). | Q-06 |
| R-022-14 | If the user does not confirm (cancels), then the system shall change nothing. | Q-28 |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-022-01 | Three contacts picked | The oldest survives; two go to Trash | R-022-01, R-022-05 |
| EX-022-02 | Same key, same value on both | No choice needed; one attribute | R-022-04 |
| EX-022-03 | Same creation time | The contact with the lower id is the survivor | R-022-02 |
| EX-022-04 | A merged-away contact is not restored within 30 days | Erased with its data (BR-04, BR-06) | R-022-05 |
| EX-022-05 | The same contact twice in the request | Refused | R-022-10 |
| EX-022-06 | One contact is already in Trash | Refused | R-022-10 |
| EX-022-07 | Chosen e-mail value invalid after combining | Cannot happen: values were valid; if it did, BR-05 refuses | R-022-09 |
| EX-022-08 | Chosen values equal the survivor's current values | Merge still confirms; others go to Trash; no version if nothing on the survivor changed | R-022-05 |

## Out of scope

Automatic merge; merging across groups; undo of a merge as one action (the user restores the contacts and the survivor's version); merging by drag and drop; a merge rule per field.
