# US-007 Rename and delete tags of a group

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

## Story

As an Owner or Editor, I want to rename or delete a tag for the whole group at once, so that I can correct a spelling or retire a category without editing every contact.

## Purpose

A typo in a tag (`udelezenec2205`) would otherwise have to be fixed on every contact by hand.

## Definitions

| Term | Meaning |
|---|---|
| Manage tags | The screen listing the tags of the group with the number of contacts for each; the place to rename or delete. [ASSUMPTION] |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-007-01 | When an Owner or Editor renames a tag to a valid new name, the system shall change the name on every contact of the group that has the tag, including contacts in Trash. [ASSUMPTION] for Trash. | Q-10a |
| R-007-02 | If the new name equals the name of another tag of the group ignoring case (BR-07), then the system shall refuse, show the reason and change nothing. | Q-10a |
| R-007-03 | When the new name differs from the old only in capitalisation, the system shall change the spelling. | Q-10a |
| R-007-04 | If the new name is not a valid tag name (US-006 R-006-03), then the system shall refuse and change nothing. | Q-10 |
| R-007-05 | When an Owner or Editor deletes a tag, the system shall remove it from every contact of the group and shall delete no contact. | Q-10a |
| R-007-06 | When a tag is renamed or deleted, the system shall not create a new version of the affected contacts (US-019). | Q-10a, Q-29 |
| R-007-07 | While the user is a Viewer, the system shall show no rename or delete control and shall refuse the request (BR-02). | Q-06 |
| R-007-08 | When a tag is renamed or deleted, the system shall write one History entry per affected contact (US-013). | Q-10a |

## Acceptance criteria

| ID | Given | When | Then | Rules |
|---|---|---|---|---|
| AC-007-01 | Three contacts have `udelezenec2205` | Ana renames it to `udelezenec2025` | All three show `udelezenec2025`; no contact has the old name | R-007-01 |
| AC-007-02 | Tags `udelezenec2025` and `gost` exist | Ana renames `gost` to `UDELEZENEC2025` | Refused with the reason; both tags unchanged | R-007-02 |
| AC-007-03 | Tag `vip` exists | Ana renames it to `VIP` | The tag is `VIP` on all its contacts | R-007-03 |
| AC-007-04 | Tag `old` is on 4 contacts | Marko deletes the tag | `old` is on none; all 4 contacts still exist | R-007-05 |
| AC-007-05 | Tag `old` on a contact with version 3 | The tag is deleted | The contact stays at version 3 | R-007-06 |
| AC-007-06 | Tag `old` on 4 contacts | The tag is renamed to `new` | The History has 4 entries, each with old and new tag name | R-007-08 |
| AC-007-07 | Petra is a Viewer | She looks at Manage tags | There is no rename or delete control; a request is refused (403) | R-007-07 |
| AC-007-08 | A rename is attempted to `neue marke` (space) | The user submits | Refused; nothing changes | R-007-04 |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-007-01 | Rename to the same name exactly | Nothing changes; no History entry | R-007-03 |
| EX-007-02 | Tag with 0 visible contacts but on a trashed contact | Still listed; rename and delete apply to it | R-007-01, R-007-05 |
| EX-007-03 | Rename to a name of 50 characters; of 51 | Accepted; refused | R-007-04 |
| EX-007-04 | After the rename, a contact would carry two tags of the same name | Cannot happen: refused by R-007-02 | R-007-02 |
| EX-007-05 | Tag deleted that no one uses | Not offered, so not deletable | R-006-07 |

## Out of scope

Merging two tags; bulk tagging of a selection; tag colours.
