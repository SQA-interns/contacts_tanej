# US-009 Contact list with search and sorting

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

## Story

As a member of a group, I want a clear list of its contacts with one search box and sortable columns, so that I find a contact in seconds.

## Purpose

Ease of use is the customer's competitive advantage. Without a quick overview and search the user falls back to Excel.

## Definitions

| Term | Meaning |
|---|---|
| List | The group's contacts that are not in Trash, shown in pages. |
| Search text | The text in the one search box. |
| Word | A part of the search text separated by spaces. |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-009-01 | When a member opens a group, the system shall show its contacts that are not in Trash, 25 per page, sorted by last name and then first name by Slovenian rules (č, š, ž after c, s, z), and the total number of matches. | Q-23b, Q-11a |
| R-009-02 | The system shall show the columns last name, first name, e-mail, phone, company, city, country and tags, and shall let the user sort by any column except tags, ascending or descending. Column set confirmed by the developer. | Q-23b |
| R-009-03 | When the user types a search text, the system shall show the contacts in which every word is a part of the value of at least one of first name, last name, e-mail, company, city, a tag name or an attribute value, ignoring case and accents (BR-07). Several words must all match (confirmed by the developer). | Q-23 |
| R-009-04 | The system shall not search phone and notes. | Q-23 |
| R-009-05 | If no contact matches, then the system shall show "No contacts match" and a "Clear filters" button that removes search text and filters. | Q-23b |
| R-009-06 | If the group has no contact, then the system shall show an empty state with a short text, and for an Owner or Editor an "Add contact" button. (confirmed by the developer) | Q-15 |
| R-009-07 | The system shall show no contact of Trash and no contact of another group in the list (BR-01). | Q-23b, Q-13 |
| R-009-08 | When the user pages or sorts, the system shall keep the search text and filters. | Q-23b |
| R-009-09 | When the user opens a contact from the list, the system shall show the contact screen (US-005). | Q-07a |
| R-009-10 | The system shall let a Viewer use the list and search exactly like other members. | Q-06 |

## Acceptance criteria

| ID | Given | When | Then | Rules |
|---|---|---|---|---|
| AC-009-01 | The group has 60 contacts | A member opens the group | The first 25 are shown, by last name then first name; "60" is shown as the total; page 3 has 10 | R-009-01 |
| AC-009-02 | Contact "Ana Škerlj" exists | A member searches `skerlj` | "Ana Škerlj" is found | R-009-03 |
| AC-009-03 | Contact "Ana Novak", company "Acme" | A member searches `ana no` | She is found (every word is part of a field); `ana xx` finds nothing | R-009-03 |
| AC-009-04 | Ana has tag `udelezenec2025` and attribute `kompetenca=spletnoProgramiranje` | A member searches `udelez`, then `spletno` | Ana is found by both | R-009-03 |
| AC-009-05 | Ana's phone is `+386 41 555 123` and her notes say "vip" | A member searches `555`, then `vip` | Neither finds her | R-009-04 |
| AC-009-06 | A search matches nothing | The result is shown | "No contacts match" and "Clear filters" appear; the button restores the full list | R-009-05 |
| AC-009-07 | A new group has no contact | Ana (Owner) opens it | The empty state with "Add contact" appears; for Petra (Viewer) the text without the button | R-009-06 |
| AC-009-08 | Contact "Ana Novak" is in Trash | A member lists and searches `novak` | Ana is not shown | R-009-07 |
| AC-009-09 | Contacts "Čuk", "Cerar", "Sever", "Šuster", "Zupan" | Sorted by last name | The order is Cerar, Čuk, Sever, Šuster, Zupan | R-009-01 |
| AC-009-10 | The list is on page 2 with search `novak` | The user sorts by city | The search text remains; the sort changes | R-009-08 |
| AC-009-11 | Petra is a Viewer | She searches and sorts | It works the same as for an Editor | R-009-10 |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-009-01 | Exactly 25 contacts; 26 contacts | One page; two pages | R-009-01 |
| EX-009-02 | Empty search text | Full list | R-009-03 |
| EX-009-03 | Search `%` or `_` or `'; DROP TABLE` | Treated as plain text; no error; no contact found unless it contains that text | R-009-03 |
| EX-009-04 | Search of only spaces | Treated as empty | R-009-03 |
| EX-009-05 | Search `ŠKERLJ` and `škerlj` | Same result | R-009-03 |
| EX-009-06 | Same last name and first name | Order is stable between pages | R-009-01 |
| EX-009-07 | Contact has no last name | Sorted at the end for ascending | R-009-01 |
| EX-009-08 | 10,000 contacts, a search | Result in under 1 second (NFR-01) | R-009-03 |
| EX-009-09 | Page beyond the last | The last page is shown | R-009-01 |

## Out of scope

Filters (US-010); selection and export (US-011); saved searches or filters; search of phone and notes; fuzzy search; full-text ranking.
